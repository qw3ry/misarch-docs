Welcome to the MisArch requirements and architecture documentation. It is based on the representable microservice reference architecture [MiSArch](https://misarch.github.io), but deviates from it in some aspects. It is tailored to research the relation between requirements and architecture. For the original reference architecture, please consult the original project.

### Documentation

See

- [Requirements](/category/requirements) for the requirements of the system. They are divided into [Domain Requirements](/requirements/domain-requirements), [Non-Functional Requirements](/requirements/non-functional-requirements), [Use Cases](/requirements/use-cases), and [Business Processes](/requirements/business-processes).
- [Architecture](/category/architecture) for the architectural design of the system, including the [domain model](/architecture/domain-model), [component diagram](/architecture/component-diagram), as well as:
    - [Components & Services](/category/components--services) for detailed documentation of every domain service or system components
    - [ADRs](/category/adrs) for the architectural decisions
